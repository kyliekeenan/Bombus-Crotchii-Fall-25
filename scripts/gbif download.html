Downloading Bee Records with Associated Host Plants from GBIF

Published

May 13, 2026

Overview

GBIF is primarily an occurrence database, not a curated bee–plant interaction database. Many useful bee–plant records are found in Darwin Core fields such as associatedTaxa, associatedOrganisms, behavior, and occurrenceRemarks.

This document shows one practical workflow for downloading bee records from GBIF and extracting records that may contain host plant, floral visitor, pollen, nectar, or other plant-association information.

Setup

# Install packages if needed
# install.packages(c("rgbif", "dplyr", "stringr", "readr", "purrr"))

library(rgbif)
library(dplyr)
library(stringr)
library(readr)
library(purrr)

GBIF credentials

GBIF occurrence downloads require a GBIF account. Store your credentials in your .Renviron file rather than typing them directly into scripts.

# Run this once to edit your .Renviron file:
# usethis::edit_r_environ()

# Add lines like these, replacing with your own credentials:
# GBIF_USER="your_username"
# GBIF_PWD="your_password"
# GBIF_EMAIL="you@example.edu"

Restart R after editing .Renviron.

Define bee families

Here we use the major bee families. GBIF taxon keys are retrieved dynamically using the GBIF backbone taxonomy.

bee_families <- c(
  "Andrenidae",
  "Apidae",
  "Colletidae",
  "Halictidae",
  "Megachilidae",
  "Melittidae",
  "Stenotritidae"
)

family_keys <- map_int(
  bee_families,
  \(x) name_backbone(
    name = x,
    rank = "FAMILY",
    kingdom = "Animalia"
  )$usageKey
)

bee_family_lookup <- tibble(
  family = bee_families,
  familyKey = family_keys
)

Request a GBIF download

This download requests bee occurrence records that have information in the associatedTaxa field.

dl <- occ_download(
  pred_and(
    pred_in("familyKey", family_keys),
    pred_notnull("associatedTaxa")
  ),
  format = "SIMPLE_CSV"
)

dl

GBIF downloads are processed asynchronously. Wait for the download to finish, then import it.

occ_download_wait(dl)

bee_dat <- occ_download_get(dl) |>
  occ_download_import()

Extract likely bee–plant association records

The following code combines several possible association fields and filters for text likely to indicate a plant interaction.

bee_plants <- bee_dat |>
  select(
    gbifID,
    bee_name = scientificName,
    bee_family = family,
    associatedTaxa,
    associatedOrganisms,
    behavior,
    occurrenceRemarks,
    eventDate,
    decimalLatitude,
    decimalLongitude,
    countryCode,
    datasetKey
  ) |>
  mutate(
    association_text = str_squish(paste(
      associatedTaxa,
      associatedOrganisms,
      behavior,
      occurrenceRemarks,
      sep = " | "
    ))
  ) |>
  filter(
    str_detect(
      str_to_lower(association_text),
      "plant|flower|floral|pollen|nectar|forag|host|on "
    )
  )

bee_plants

Save the results

write_csv(bee_plants, "gbif_bee_associated_plants.csv")

A broader search

Some useful bee–plant associations may not be stored in associatedTaxa. They may appear instead in associatedOrganisms, behavior, or occurrenceRemarks. A broader download can search for records where any of these fields are populated.

dl_broad <- occ_download(
  pred_and(
    pred_in("familyKey", family_keys),
    pred_or(
      pred_notnull("associatedTaxa"),
      pred_notnull("associatedOrganisms"),
      pred_notnull("behavior"),
      pred_notnull("occurrenceRemarks")
    )
  ),
  format = "SIMPLE_CSV"
)

occ_download_wait(dl_broad)

bee_dat_broad <- occ_download_get(dl_broad) |>
  occ_download_import()

Then apply the same text filtering approach:

bee_plants_broad <- bee_dat_broad |>
  select(
    gbifID,
    bee_name = scientificName,
    bee_family = family,
    associatedTaxa,
    associatedOrganisms,
    behavior,
    occurrenceRemarks,
    eventDate,
    decimalLatitude,
    decimalLongitude,
    countryCode,
    datasetKey
  ) |>
  mutate(
    association_text = str_squish(paste(
      associatedTaxa,
      associatedOrganisms,
      behavior,
      occurrenceRemarks,
      sep = " | "
    ))
  ) |>
  filter(
    str_detect(
      str_to_lower(association_text),
      "plant|flower|floral|pollen|nectar|forag|host| on |visiting|visited"
    )
  )

write_csv(bee_plants_broad, "gbif_bee_associated_plants_broad.csv")

Optional: download as Darwin Core Archive

For a more defensible archival download, use Darwin Core Archive format. This preserves more of the original data structure, including verbatim fields.

dl_dwca <- occ_download(
  pred_and(
    pred_in("familyKey", family_keys),
    pred_notnull("associatedTaxa")
  ),
  format = "DWCA"
)

Caveats

The field associatedTaxa does not necessarily mean “host plant.” It may contain host plants, flowers visited, parasites, predators, nest associates, or other associated taxa.

Before using these records in an analysis, you should inspect the association text and separate true plant associations from other biological associations. A conservative workflow would include manual checking, taxonomic name cleaning, and classification of the interaction type, for example:

  • host plant
  • floral visit
  • pollen source
  • nectar source
  • plant substrate
  • ambiguous plant association
  • non-plant association

Suggested next step

After downloading the raw data, the next step is to parse association_text into separate fields such as plant_name_raw, interaction_type, and evidence_field. That curation step is essential before treating the output as a bee–host plant interaction table.
